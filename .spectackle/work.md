## P-0040 token economy: teach agents to replace shell grep/find/sed exploration with server tools
kind: proposal
state: active
created: 2026-07-24
grilled: 2026-07-24

Requirement: wherever it saves tokens, agents working a spectackle repo should use the MCP server instead of shell find/grep/sed. Today neither the initialize instructions, the workflow prompt/template, nor docs/agent-workflow.md map shell habits to server tools — an agent with shell access defaults to grep/find and pays O(codebase) content tokens for what the server answers in O(results) ID+span records. Fix (wording authored here, pasted by one implementer): a TOKEN ECONOMY paragraph with the substitution map — grep/rg symbol -> find q= scope=code (ranked n-records, focus for proximity); grep -r over specs/history/rejections -> find scope=rule|rejection|history (FTS5); find(1) by filename -> find scope=code matches file paths too (SPX-GRA-003); where-defined/what-depends -> get id= depth=N instead of chained greps; pre-bulk-edit site survey -> get depth + check after, sed only for the edit itself; NEVER grep/sed .spectackle/ files (server-owned, SPX-ARC-005); rule of thumb: shell returns file contents, server returns IDs+spans — use shell only to read actual bytes of one known file. Delivery points: (1) server.go instructions const; (2) templates/commands/workflow.md.tmpl (regenerate all four harness surfaces via commands op=gen); (3) prompts.go workflow prompt step 1; (4) docs/agent-workflow.md subsection. Exit criterion (explicit): new test asserts the instructions const contains the TOKEN ECONOMY guidance; regenerated AGENTS.md/.claude/.github files carry it (git diff shows all four); full suite -race green; lint clean. Rollback: revert diff, wording-only. Scope: internal/mcpserver/server.go, internal/mcpserver/templates/commands/workflow.md.tmpl, internal/mcpserver/prompts.go, internal/mcpserver/tools_test.go, docs/agent-workflow.md + generated AGENTS.md, .claude/commands/*, .github/prompts/*.
