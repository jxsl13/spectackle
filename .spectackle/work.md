## P-0066 ADR migration tool: server-side rewrite of legacy D-ids, and stale pre-rebrand rule text
kind: proposal
state: active
created: 2026-07-24
grilled: 2026-07-24

Two related gaps found by inspecting the living spec after the ADR rename landed. (1) MIGRATION IS BLOCKED WITHOUT A TOOL: the user asked for a FULL migration of legacy decision records to ADR ids. Parts 1+2 shipped (kind/ID rename, ADR fields, searchable). Part 3 cannot be done the way the others were: the two legacy records ADR-0003/ADR-0004 are now archived, so they live only as journal tombstones, and rewriting journal history by hand is exactly what the architecture forbids (the LLM never edits .spectackle; only the server writes it). The honest fix is to give the SERVER a migration path: a `migrate-adr` CLI subcommand that rewrites D-<nnnn> ids to ADR-<nnnn> across every .spectackle work.md and journal.ndjson in the workspace, dry-run by default, idempotent, refusing to run when a target ADR id already exists. That turns a forbidden hand-edit into an auditable, testable server operation. (2) STALE PRE-REBRAND RULE TEXT: root spec.md still carries pre-rebrand wording — SPX-ARC-001 says 'The spectacle server' and SPX-ARC-005 says '.spectacle folders' (single c, the old name), and SPX-SWM-007 still says the server mints 'a linked `decision` item' although the kind is now adr. These are contract sentences an agent reads as ground truth, so the drift is user-visible and worth fixing via rule op=edit (server write path, orchestrator's job). Exit criterion (explicit): a migrate-adr subcommand exists, defaults to dry-run listing every id it would rewrite, applies only with an explicit flag, is idempotent (second run reports nothing), refuses on id collision, and is covered by tests over a fixture workspace containing both a live work.md item and journal tombstones; the three stale rule sentences read correctly (spectackle, .spectackle, adr) and lint stays clean. Rollback: revert the tool; rule edits are revertible via rule op=edit. Scope: internal/migrate (new) + cmd/spectackle/main.go + tests for the tool; the rule text fixes are orchestrator-side rule calls.

## P-0067 migrate the architecture decision docs to structured ADRs in the server
kind: proposal
state: active
created: 2026-07-24
grilled: 2026-07-24

User requirement: architecture decisions must live as structured, searchable ADRs in spectackle, not as unstructured markdown in docs/. Inventory (measured): docs/ holds 15 files, of which exactly FOUR are decision documents — they all carry an explicit 'Status: research/PoC' header and record a choice with rationale: design-go-types-calls.md (129 lines, go/types-based call resolution), design-incremental-index.md (137, whether memGraph needs a delete/ownership path), design-wasm-parsers.md (192, wazero x tree-sitter feasibility), design-wasm-poc-c.md (241, the C PoC scored against that design's exit criteria). The other eleven are reference documentation (architecture, tools, ears, spec-cascade, lifecycle, agent-workflow, roadmap, cookbook-new-language, example-go-cuda, release) or an evidence report (validation-ddnet) — those are NOT decisions and must stay as docs. Plan: for each of the four, mint a LIVE ADR carrying the classic template — Context (the forces), Decision (what was chosen), Consequences (what it costs/enables), Status=accepted — via the decide tool, then reduce the doc to its durable value (the measurements, tables and evidence) with a header pointing at its ADR id. Note the wazero case specifically: ADR-0002 (defer) and ADR-0004 (reopen-poc) already exist but are ARCHIVED tombstones minted before the ADR fields existed, so the new ADR consolidates that thread and must record the user's correctness-first framing (parser fidelity is the primary axis; latency is amortizable via the parse cache; the real blocker is WASI grammar availability for CUDA/ObjC). Division of labor: reading ~700 lines of design docs is delegated to an implementer that EXTRACTS and REPORTS the four field-sets (it must not write .spectackle — minting is a server write and stays with the orchestrator); the orchestrator mints the ADRs from the reviewed extraction and adds the doc pointers. Exit criterion (explicit): four live ADR items exist, each with non-empty Context/Decision/Consequences and Status=accepted, each findable via find scope=adr; each of the four docs opens with a pointer to its ADR id; no reference doc was converted; check ok, lint 15/61/0. Rollback: move the ADRs to rejected and git checkout the docs.
