## P-0061 one-call re-audit: check heals the mechanical drift AND reports every heal with its audit material
kind: proposal
state: draft
created: 2026-07-24
grilled: 2026-07-24

Synthesis of the two rejected extremes (P-0060 silent auto-restamp = accepts unverified code; pure manual re-audit = the ten hand calls this cycle). User requirement: ONE tool call that does both — heal what is mechanically safe, and in the SAME response hand the LLM everything needed to validate each heal at a glance, so it can afterwards make dedicated corrections. NOTE the current half-state: check fix=true ALREADY re-stamps Changed anchors and drafts a backprop, but blindly (no direction awareness) and without showing what the contract says or what the code now is — so a reviewer cannot judge it. Design: (1) DIRECTION-AWARE CLASSIFY (from P-0060, the part that survives): compare BOTH stored hashes — CHash (code span) and the currently unused RHash (rule sentence) — yielding: ok; ImplementationEvolved (code changed, rule identical); ContractTightened (rule changed, code identical — today invisible and the dangerous direction); Diverged (both changed); plus existing gone/stale/pending. (2) HEAL ONLY THE MECHANICAL CLASS: ImplementationEvolved gets its CHash re-stamped in the same call. Nothing else is ever healed automatically. (3) NO SILENCE — every heal is reported in the same response with its audit material, deduped for token economy: one `d healed <rule> <node> <file>:<s>-<e> was=<old8> now=<new8>` line per anchor, plus ONE `r <rule> <pattern> <dir> <text>` line per distinct rule involved (the contract that still binds, printed once even if several anchors share it). That is exactly what a reviewer needs to judge 'does the new code still satisfy this sentence?' without a second round trip. (4) THE RISKY CLASSES ARE NEVER HEALED: ContractTightened and Diverged emit `d audit <rule> <node> ...` with the same rule text, and (fix=true) draft a backprop proposal. (5) MACHINE AUDIT WHERE AVAILABLE: if the workspace configures an audit command (sibling of the existing feedback.grill shell hook in FeedbackCfg), check runs it per healed/audited anchor with the rule text + file + span; a non-zero exit downgrades a would-be heal to `d audit` with the command output as the finding — so heals are machine-verified wherever the project supplies a verifier. (6) TRAILER + FOLLOW-UP: a summary line `ok healed=N audit=M` closes the block; every heal is journaled (auditable, git-reversible), and the LLM's dedicated follow-up is the normal path — rule op=edit if the contract should change, or draft a backprop if the code is wrong. (7) LIFECYCLE GATE: move to=done refuses while the item's scope has open `d audit` obligations (heals do not block). Exit criterion (explicit): unit tests per quadrant incl. an RHash-only change; a check run after editing an anchored function emits `d healed` + the rule text and leaves check ok, with zero manual rule calls; a rule-text-only edit emits `d audit` and never heals; the rule line is printed once for multiple anchors of the same rule; audit-command non-zero exit demotes a heal to audit; move-to-done gated on open audits; go test ./... -race green; docs/tools.md check grammar + docs/lifecycle.md document the classes and the heal/audit split. Rollback: revert; anchors.tsv format unchanged. Scope: internal/drift/drift.go+test, internal/mcpserver/tools.go (check), internal/workspace (audit command config), internal/lifecycle (done gate), docs.
